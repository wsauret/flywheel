# Why this task exists

This medium task measures whether a model can follow one value from configuration through durable session telemetry, the runtime protocol, and the TUI. A weak plan can find a cost label and add a local comparison. A strong plan must preserve the existing state ownership and recovery model.

## Must-address verification

1. **Configuration ownership and money validation.** `src/orchestration/config/schema.ts` defines `BudgetConfigSchema` and uses `DEFAULT_BUDGET` from `src/workflows/budget.ts`. The current fields use a non-negative integer schema, so a USD limit requires an explicit decimal-safe schema choice. This point catches plans that edit a sample TOML file but do not change the decoded configuration contract.
2. **TOML loading and configuration tests.** `src/orchestration/config/loader.ts` parses TOML in `loadTomlFile`, merges it in `loadConfig`, and decodes `FlywheelConfigSchema`. `tests/unit/orchestration/config/config.test.ts` already tests budget defaults, TOML budget values, and invalid configuration. This point catches plans that add a field without proving load and validation behavior.
3. **Existing durable cost projection.** `src/orchestration/session/budget-projection.ts` stores cost in `BudgetProjectionState.totalCost`. Its `foldCumulativeReading` function computes per-stream deltas and separates parent and subagent baselines. `tests/unit/orchestration/session/budget-store-accumulation.test.ts` verifies cumulative results, process restarts, and interleaved subagents. This point catches a duplicate counter that can drift or double-count.
4. **Store and event bus roles.** `createSessionBudgetStore` records facts, applies the projection, and emits `budget.metrics.changed`. `wireSessionSubscribers` receives that event and writes the current metrics patch. This matches the project rule that UI state belongs in a store while the bus carries infrastructure notifications. This point catches plans that make the event bus or a latch the source of warning state.
5. **Protocol snapshot and patch contract.** `BudgetView` defines the budget data sent to clients. `createBudgetProtocolProjection` builds snapshots and ordered `budget.updated` patches through `budgetView` and compares changes through `sameBudget`. `BudgetViewSchema` validates the same wire shape. This point catches plans that update only one protocol representation.
6. **TUI protocol intake.** `createBudgetCache` is the ordered per-session snapshot and patch receiver. `createShellState` binds that cache to `signals.budgetView`. This point catches direct TUI imports of the session store and duplicate Solid signals.
7. **Existing warning presentation patterns.** `createHeaderDisplay` already derives cost and context from the foreground `budgetView`, applies terminal-width gates, and has warning colors. `statusRows` also renders usage from `BudgetView`. `formatCost` is the shared USD formatter. This point catches a new formatting rule or a presentation path that ignores narrow terminals.
8. **Resumed and inactive session accuracy.** `readBudgetSummaryFromReader` rebuilds totals from the same budget projection. `projectDurableHistorySessionView` uses that summary for durable session rows and budget views. This point catches persistence of warning state in metadata or a live-only threshold comparison.
9. **Focused regression coverage.** The named tests are the existing seams for cumulative spend, budget protocol publication, ordered cache recovery, and header rendering. This point catches plans that rely only on a broad suite and do not test the threshold boundary or recovery path.
