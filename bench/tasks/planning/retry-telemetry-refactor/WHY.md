# Why this task exists

This broad trapped-refactor task measures whether a planning Chat reconciles a plausible user request with the current repository before it writes implementation phases. The requested consolidation is real: live trace collection and durable replay both maintain span lifecycle state, and the path crosses runtime facts, direct event-bus correlation, session fact persistence, strict replay, lineage reads, and ordered resource disposal. A weak plan can repeat the brief's stale assumptions. A strong plan must flag each false claim, reuse the current parentage policy, and enumerate every production edge before it proposes a shared transition model.

## Refactor seam

`createTraceCollector` in `src/orchestration/session/trace-collector.ts:66-305` owns live open and ended span state, writes start/completion/finalization facts, and delegates runtime event correlation to `subscribeTraceEvents`. `src/orchestration/session/trace-projection.ts:48-131` independently folds open and completed spans for replay. Both use the parent policy from `src/orchestration/session/trace-event-types.ts:57-79`, which is an existing solution that the refactor must preserve rather than duplicate. The seam has genuine multi-consumer coupling: `src/orchestration/session/tool-execution-store.ts:36-121` emits trace correlation events only after stored runtime facts are projected; `src/orchestration/session/create-session-infra.ts:49-83` orders persistence, projection updates, and subscription wiring; chat and workflow install that wiring at `src/orchestration/chat-session.ts:100-102` and `src/orchestration/workflow-host-factory.ts:185-191`; lineage replays the facts at `src/orchestration/session/lineage-inspector.ts:73-113`.

## False claims and refuting evidence

1. **Stale symbol: event subscribers still call `recordSpan`.** `TraceCollector` exposes only `startSpan`, `endSpan`, `subscribeToEvents`, `finalize`, and `dispose` at `src/orchestration/session/trace-collector.ts:45-51`. The subscriber dependency has only `startSpan` and `endSpan` at `src/orchestration/session/trace-subscriptions.ts:7-10`, and `tests/unit/orchestration/session/trace-collector-span-tree.test.ts:88` explicitly records that `recordSpan` was removed.
2. **False invariant: asynchronous trace delivery can persist completion before start.** Trace graph subscribers use direct delivery specifically to preserve emit order at `src/orchestration/session/trace-subscriptions.ts:73-76`. Live collection opens the span before publishing `span.started` at `src/orchestration/session/trace-collector.ts:192-205`, and publishes `span.completed` before removing the open span at `src/orchestration/session/trace-collector.ts:231-235`. Replay rejects a completion without a prior open start at `src/orchestration/session/trace-projection.ts:109-113`; it does not repair it.
3. **Dead-code lie: the finalization writer is unused.** `recordTraceFinalized` is defined at `src/orchestration/session/trace-collector.ts:30-32` and called from `finalize` at `src/orchestration/session/trace-collector.ts:263-275`. `tests/unit/orchestration/session/trace-store.test.ts:59-78` verifies the final summary and exact persisted order, while `tests/unit/orchestration/session/trace-collector-finalize.test.ts:38-69` verifies summary publication and disposal finalization.
4. **Wrong location: durable trace schemas live in infra.** The schemas and parser are defined in `src/orchestration/session/trace-event-types.ts:81-117`. `src/orchestration/session/session-fact-registry.ts:13-33` registers them as session facts, and `src/orchestration/session/session-event-writer.ts:14-18` includes `TraceFact` in the session writer union. Infra provides generic fact and trace value primitives, not the durable session trace schema.

## Must-address verification

1. **Stale recordSpan claim.** This point prevents a plan from creating or migrating callers for an API that no longer exists.
2. **Strict start-before-completion invariant.** This point requires `CLAIM_INVALID` handling and protects strict replay from speculative repair behavior.
3. **Live finalization publication.** This point catches deletion of live code and preserves the durable trace summary.
4. **Actual trace schema ownership.** This point catches a move to the wrong layer and preserves the session fact registry as the schema owner.
5. **Canonical lifecycle transition seam.** This point is the genuine DRY obligation: consolidate the duplicated live/replay transition rules while reusing the existing parent policy.
6. **Event correlation surface.** `src/orchestration/session/trace-subscriptions.ts:78-208` subscribes to workflow, step, worker, tool, and subagent lifecycle events. Its maps, follow-up filtering, nested parent resolution, cost baseline, and direct delivery are behavioral constraints a broad refactor must retain.
7. **Persisted tool fact source.** `src/orchestration/session/tool-execution-store.ts:36-63` applies stored facts before trace emission, and `:69-121` emits the four tool/subagent events with identity fields. This point prevents trace collection from bypassing the durable runtime projection.
8. **Complete construction and wiring callers.** The sole production collector construction is `src/orchestration/session/session-resources-service.ts:157-193`; `wireSessionSubscribers` installs it at `src/orchestration/session/create-session-infra.ts:81-83`; chat and workflow are its two production callers. This point catches a plan that updates one session mode only or breaks tracing-disabled sessions.
9. **Durable fact and diagnostic contracts.** Session writer and registry references make the facts writable and decodable. `src/infra/event-search.ts:41`, `src/cli/event-search-format.ts:41-49`, and `src/cli/event-search-args.ts:185` also consume the stable event names, so a lifecycle refactor must not silently rename its diagnostic surface.
10. **Replay and lineage consumers.** `src/orchestration/session/lineage-inspector.ts:36,50-63,110` is the only production caller of trace replay. It is constructed in both the main runtime at `src/orchestration/app-service/runtime-composition.ts:184-203` and the background reader at `src/orchestration/app-service/runtime-background-worker.ts:37-54`. This point preserves foreground/background lineage equivalence.
11. **Lossless shutdown sequencing.** `src/orchestration/session/session-resources-service.ts:65-75` documents bus drain before trace finalization and writer disposal, while `:208-255` implements the lifecycle operations. `src/orchestration/workflow-host-lifecycle.ts:8-20` exposes that order to the workflow VM. This point prevents final facts from being dropped or late events from escaping collection.
12. **Focused no-regression proof.** The named unit tests cover strict live/replay parentage, the persisted runtime-fact path, final fact order, finalization, cost deltas, lineage, and Effect disposal. The concrete `bun run test -- ...` command gives the implementation phase a narrow behavioral gate instead of relying only on compilation.
