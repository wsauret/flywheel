When I stop a background command from /bg, its row says "Stopped · exit 1". The command never exited with 1. I stopped it, and a signal ended it. The agent also gets a completion note that says the command "exited with code unknown", which makes no sense to it. A command that a signal ended must not get an exit code it never had, and the agent should be told which signal ended it. Commands that exit on their own must keep their real exit code. Also, a stopped or canceled row in /bg should never show an exit code. If the command traps the signal and exits with 143, or Windows sets 1 when it ends the job, that number is only the reaction to my stop, not the result of the command.
