## Design Context

### Users
Developers who use AI-assisted coding tools (Claude Code, Cursor, Aider, etc.) and discover Flywheel through open source communities. They are technical, opinionated about their terminal setup, and will judge the tool in seconds. They run it in full-screen terminals, tmux panes, and IDE integrated terminals — dark theme environments are the norm.

### Brand Personality
Clean, modern, lightweight, delightful. Flywheel should feel like a well-crafted modern application that happens to live in the terminal — not a throwback to DOS-era TUIs with color slapped on top.

### Emotional Goals
- **Calm confidence**: The system has this handled. Progress is visible, state is clear, nothing feels uncertain.
- **Empowered choice**: Users feel like they have options to do things exactly the way they want. The interface surfaces paths forward without being prescriptive.

### Aesthetic Direction
- **Theme**: Dark mode is the primary design target. Light mode should work but dark is the canonical experience.
- **Warmth**: The current warm orange primary + purple accent palette is the right foundation. Lean into warmth over cold/clinical.
- **Contrast**: Low-to-moderate contrast. Avoid anything that hurts the eyes — harsh whites on pure black, saturated colors fighting for attention. Subtlety and breathing room over density.
- **Modern terminal app**: Think of it as a modern GUI that renders in a terminal, not an ASCII art project. Use Unicode thoughtfully (braille spinners, subtle box drawing) but don't let it feel retro.
- **Lightweight feel**: Generous spacing, clear hierarchy, nothing cramped. The interface should feel airy even when displaying complex output.

### Anti-References
- **lazygit**: Too contrasty, hurts the eyes. Avoid harsh color clashes and dense layouts.
- **claude code**: Technically fine but no delight. Avoid the purely utilitarian, emotionless feel.
- **btop/htop**: Too ASCII, too dense, too retro. Flywheel is a modern application, not a system monitor.

### Design Principles
1. **Calm over loud** — Low-moderate contrast, muted accents, generous whitespace. The interface should feel restful during long sessions.
2. **Modern terminal-native** — Use the terminal as a capable rendering surface, not a limitation. Unicode, true color, and subtle animation make it feel like a real application.
3. **Delight through craft** — Small touches matter: shimmer animations, smooth transitions, thoughtful status indicators. These signal care without being flashy.
4. **Progressive disclosure** — Start simple, reveal depth through interaction. Surface options without overwhelming. The user should always feel like they have paths forward.
5. **Hierarchy through subtlety** — Use weight (bold/dim), opacity, spacing, and selective color to create hierarchy. Never rely on high contrast or saturated color alone.
