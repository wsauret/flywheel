# Performance Review Principles

Use this lens with exactly one active target: `code-review` or `plan-review`. If neither is active, load the target that matches the artifact. If both are active, stop and require one target. Return through that target's locations, severity, and result contract.

Assess realistic data volume and call frequency, algorithmic complexity, query and I/O multiplicity, memory growth and retention, bounded concurrency, latency budgets, caching ownership and invalidation, and measurement evidence. Before comparing versions or hosts, confirm that each metric uses the same clock, boundary, and meaning. Show that the instrument responds to a controlled change. Use interleaved paired runs (ABBA) of identified builds and workloads, and disclose host load. Count expensive underlying work, including native measurements, equal-value publications, callbacks, and cache misses, not only outer helper calls. Pair operation counts with user-perceived latency. Name N+1 work and unbounded resource growth precisely. Treat derived state that is recomputed instead of advanced as a defect: a handler that runs per change, tick, subscription, or loop item and rereads or refolds full history, or reads each member of a collection, does work that grows with history or membership on every change; the correction reads the state its owner already keeps current and folds only what is new, and its proof counts reads per change against the number of members. Treat diagnostics as a resource: a record at default level on a per-call, per-request, or per-iteration path, content (message text, tool output, prompts, file content) in a log record, a start and done pair where one done record would serve, and a repeated condition that is not coalesced are volume defects; a decision that ends, refuses, restarts, or releases work with no record is a debuggability defect. Reject scale concerns that the system does not encounter; state the unsupported workload assumption rather than inventing a defect. Prefer measurement and the smallest correction that satisfies the demonstrated workload.

This package supplies performance principles only. Do not acquire target evidence, define severity or locations, select reviewers, route workflow work, or synthesize findings.
