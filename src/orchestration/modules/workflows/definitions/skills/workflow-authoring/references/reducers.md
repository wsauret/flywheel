# Registered Reducers

A phase's `join` names one of these reducers in `join.reducer` and passes its parameters in `join.with`. The launch pins the latest version. A reducer calculates and never judges: it counts, deduplicates by an explicit key, ranks by a declared field, or computes complements. `flywheel workflow reducers` prints the same list.

"Agents" below is the agent count of the joined phase: for a phase over a list, the `max` of its source list, or the item count of a launch input list without `max`, times `votes` for a phase with votes; for a phase of named agents, the number of its agents. The `max` of each output list is what a later phase over that list counts in the worst case. An agent key is the item's `unique` key, or its position in the list when the list declares none, or the agent's name for a named agent. An agent of a phase with `votes` adds its vote number, such as `src/a.ts:42#2`.

| Reducer | Parameters | Output | Use it for |
|---|---|---|---|
| `collect@1` | none | `total`, `completed`, `failed` counts, and `items`: one per agent with `key`, `disposition`, and a `handoff` reference, ordered by key. `items` has `max` agents. | Hand every agent's handoff to the next phase. |
| `coverage@1` | `priority`, `outcome`, `exclusions` (optional) | `status` (full, partial, or empty), `required` and `supporting` tiers with numerator, denominator, `surveyed`, and `unsurveyed` keys, plus `inaccessible`, `excluded`, `failed`, and `items` with a `handoff` reference each. `items` has `max` agents. | A survey that must state what it reached. `priority` names an item enum of required and supporting. `outcome` names an enum of the last phase of the stream of surveyed, inaccessible, and excluded. `exclusions` names a list of the source output that names the targets left out. An exclusion list that repeats a key, or that names one of the targets, fails the whole run when the phase expands, so tell the agent that writes it to list each key once and never a target. |
| `dedupe@1` | `items`, `by` | `kept`, `dropped` with a reason, and `failed`. `kept` declares `unique: <by>` and has `max` agents times the `max` of the `items` list. | Merge overlapping findings before expensive work. `items` names a list of the output of the last phase of the stream, and `by` names the required string key of its items; refer to "Keys" below. The first item for each key, in agent-key order and then list order, wins. |
| `dedupe@2` | `items`, `by` | The output of `dedupe@1`. | The version that the launch pins. In a repeat that runs its phase in rounds, it also drops each item whose key an earlier round kept or dropped, with the reason `seen in round N`, so a repeated item never keeps the repeat running. Outside a repeat, it folds as `dedupe@1` does. |
| `top@1` | `items`, `by`, `count`, `order` | `kept` (at most `count`, in rank order, so its `max` is `count`), `dropped` with a reason, and `failed`. | Keep the best N. `by` names a required number or enum; an enum ranks by its declared order, first lowest. `order` is desc or asc. With `unique` on the `items` list, ties break on the item key, then the agent key, and each key is kept once. Without it, ties break on the agent key, then list order. |
| `quorum@1` | `vote`, `min_valid`, `max_refuted`, `group_by` (optional) | `passed` and `rejected` verdicts with the valid, refuted, and abstain counts and the reason, and `failed`. With `group_by`, one verdict for each value, and the lists declare `unique: group` and have `max` agents. Over a phase with `votes`, one verdict for each item, with the item's `key` and `label`, and the lists declare `unique: key` and have `max` items. The verdicts hold counts only, not the reasons of the votes. | Adversarial verification. `vote` names an enum of the last phase of the stream of exactly valid, refuted, and abstain. A verdict passes with at least `min_valid` valid votes (at least 1) and at most `max_refuted` refuted votes. A failed agent abstains. To cast several votes on each item, set `votes` on the phase: each item gets its own verdict, a `group_by` is refused, and a `min_valid` above `votes` is refused. Otherwise `group_by` names a required string field of each item, and each value gets one verdict over its agents; refer to "Keys" below. The key of the source list holds one agent for each value, so a `group_by` on that key with `min_valid` above 1 is refused. Only `quorum` counts votes, so a phase with `votes` needs it. |

## Keys

A `dedupe` `by` and a `quorum` `group_by` compare their values as exact strings, with no normalization. So build the key only from facts that an agent cannot phrase differently, such as a repository-relative path, a line number, or a symbol name. Never key on a slug, a title, or an id that the agent invents: each agent and each round phrases it differently, so one bug gets a new key every time, duplicates survive, and a repeat never runs dry.

- Declare one key field in the agent's output contract, and state its exact format in its description, such as ``Exactly `<path>:<line>`, such as `src/a.ts:42`. Build it only from path and line.`` Declare each fact that the format names as a field of its own.
- A later agent that copies a key, such as an agent that names the finding of each verdict, copies it character for character.
- Trade-off: two reports of one bug on different lines stay separate, so a later triage or report phase merges them by cause. Two different defects on one line share a key, and only the first survives. Each other one goes to `dropped`, which holds only its key, the key of its agent, and the reason, never the finding itself, so no later phase verifies or repairs it. Tell each finder to put every defect of one line in one finding. That does not stop two agents from reporting different defects on one line, so give the phase that acts on the findings the whole handoffs (next bullet), and tell it to look up each `dropped` entry there.
{{if:type:reviewer}}
- `dedupe`, `top`, and `quorum` keep only the fields of each item in their lists, not the rest of each handoff. `collect` and `coverage` carry every whole handoff. After a phase of named agents, a later phase receives the rest, such as each reviewer's verdict on the recorded deviations, only through a `reads` that names each agent beside the phase, such as `reads: [review, quality, elegance]`. `reads` cannot name the agents of a phase over a list, so when a later phase needs more than the kept items, keep that phase's default `collect` join and let one agent merge the findings.

## Composition rules

- A phase over a list can read a list of a join output as its source: `kept` of `dedupe` or `top`, `items` of `collect` or `coverage`, or `passed` of a `quorum` with `group_by` or over a phase with `votes`.
- `dedupe` and `top` add a `branch` field to each kept item, so an item of their list cannot declare its own `branch` field.
- A join folds only after every agent settles, so its result does not depend on the order in which the agents finished.
- A repeat whose `while` names a join needs a `dedupe` join. A phase after the repeat reads the lists of every round, so each list has `max` rounds times its `max`.
