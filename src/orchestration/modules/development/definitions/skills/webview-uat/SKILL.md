# Web Client UAT

Input: client acceptance criteria, installed revision, the host under test (machine-local browser, hosted phone app, or both), configured auth and provider state, and a session scratch directory.

Compose generic UAT. The client is one bundle every host mounts, so a criterion is proven in a browser first and in an editor only when the editor host itself changed. Prepare the runtime with the `flywheel-uat` driver: `bun run uat:tui start` makes the isolated HOME, clones the effective profile's credentials by the shared credential contract in `scripts/uat/harness.ts` (`auth.json`, optional `profile.json`, and a token-free reference for each Claude login, which a Claude sign-in criterion also uses), sets `FLYWHEEL_AUTH_PROFILE`, makes a scratch project with `git init`, and launches the installed binary rather than `bun run dev`. To test a build that is not your own installed one, install it with its staged `install.sh` under a scratch HOME with `FLYWHEEL_INSTALL_DIR` and `FLYWHEEL_NO_MODIFY_PATH=1`, then pass `FLYWHEEL_INSTALLED_BINARY` and `--installation-home` to `start`. Keep unix socket paths under 104 bytes: pass a short `--scratch-root`, through a symlink if the session scratch is deep.

Two hosts reach the client. For the machine-local browser, run `bun run uat:tui web <handle>`. It runs the installed `flywheel web` in the sandbox project with the sandbox HOME and environment and prints the hub address it opened; drive that address. The command finds or starts the account service, opens the project, and opens the account hub, which leads to the project listener with the project's browser token. Do not substitute a source preview page or `bun run dev`: they do not prove the installed machine-local browser path or its bundled webview payload. The person's own service holds the fixed hub `http://127.0.0.1:41000/`, so a sandbox never uses it: every sandbox launch carries the release harness's isolated hub environment, the sandbox's service binds an ephemeral hub port and writes its origin to `<handle>/hub-origin`, and `flywheel web` opens that origin. A `flywheel web` run by hand in the sandbox needs the same `FLYWHEEL_INTERNAL_RELEASE_HARNESS`, `FLYWHEEL_INTERNAL_RELEASE_HUB_PORT=0`, and `FLYWHEEL_INTERNAL_RELEASE_HUB_RECORD=<handle>/hub-origin`, or it refuses to open anything. The sandbox hub remains available while zero projects are open. For the hosted phone app, run the installed TUI in tmux with the same HOME and `FLYWHEEL_TEST_SUPPRESS_AUTO_DIALOGS=1`. Type `/remote`, press `p`, and rebuild the pairing link from the pane, which wraps it across lines; open the link in the browser pane at `remote.flywl.sh`, then select the machine. A device store is per origin and per installed app, so a Safari tab, a Home Screen app, and the browser pane each pair on their own. Navigating to a fragment on an origin the tab already shows changes the hash and never reloads, so reload the bare origin when the deployed bundle changed.

Set `FLYWHEEL_TEST_SUPPRESS_AUTO_DIALOGS=1` on installed TUI launches used for account setup or sibling-terminal checks. Use `0` only for automatic-dialog criteria, as specified in `flywheel-uat`. This is a TUI launch setting, not a server, browser, or editor setting.

Drive the client through what a person touches. Command panel rows pick on `mousedown`, not `click`. Sheets open from the slash button's panel by row label and close through the header's Close button; a sheet that opens another sheet is a distinct path from the panel. The mobile preset emulates a coarse pointer and the desktop preset a fine one, so check both rungs of a control that has them. `agent-browser screenshot` saves to the current directory, which is the repository, unless it gets a path, so always pass an absolute path in the session scratch directory. The browser pane cannot screenshot while it is hidden; computed styles, bounding rectangles, `document.activeElement`, and the console still work, and the client reports every failed read through `console.warn` with the runtime's own error, so read the console before guessing. On macOS, `agent-browser press` and CDP key events can start a stream of trusted keydowns that does not end until the browser restarts; it starves the page's main thread, so timers, socket handling, and every timing observation after it are false. Drive keys a criterion does not name through the DOM: set the composer value, dispatch an `input` event, and call `click()` on the control. When a criterion needs a real key press, restart the browser after it and before any timing evidence. Send one bounded prompt when a criterion needs a turn, wait for the Stop button to leave, and read the transcript blocks by class. Record exact observations.

For account-service and local-wake acceptance, use agent-browser against one isolated account HOME and two isolated git projects. Set `FLYWHEEL_INTERNAL_RESIDENT_SERVICE=1` in that environment, because a service in a HOME that is not the login home retires once nothing holds it. First load the sandbox hub from `<handle>/hub-origin` with zero known projects and record the empty state. Open A through installed Flywheel, release its clients, wait for it to become asleep, and reload the sandbox hub; with exactly one known project, record automatic POST wake through starting to ready. Add B, release it to asleep, and record two rows plus a manual Wake for B. Make a project's SQLite path temporarily unopenable, request wake, and record the sanitized failed state and Try again control without a path or credential; restore access, retry, and record ready. Capture the sandbox hub at 1440x900 and 390x844. Keep A open in both a terminal and browser, submit one bounded message, and prove both show the same session and output. Reload the browser within idle grace and prove A stays open. Keep B held by a sibling terminal or sealed relay, release A's final browser and terminal holds, and after grace prove only A's project endpoint disappears while B, the `flywheel serve` pid, and the sandbox hub port remain. Record the service pid and descendant tree at zero, one, and two open projects.

The hosted phone app is a bootstrap that loads the phone shell and the client from the paired machine through the relay, under the identity the machine's build states, so a client change reaches the phone with the runtime that serves it and deploys nothing; `bun run --cwd relay deploy:app` publishes only the bootstrap, a rare change the person decides on. Run the installed `flywheel remote projects forget <scratch-project-root>` in the sandbox environment for every scratch project, then finish with `bun run uat:tui stop <handle>`, which stops the isolated account service, removes the isolated HOME and copied credentials, and ends the tmux session. Never kill by broad process name or touch the active development runtime. Stop when every criterion has a generic UAT status or the environment is blocked. Return installed revision, host, sandbox and pairing identity without secret values, interactions, observations, console diagnostics, criterion statuses, and cleanup state. A failed `flywheel web` handoff, a failed pairing, or a hidden pane where a criterion needs a rendered frame returns `blocked` with the reason.
